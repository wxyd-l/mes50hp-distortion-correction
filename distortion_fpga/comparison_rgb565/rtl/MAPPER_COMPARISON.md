# 查表与公式计算的统一对照

项目保留原查表方案，并增加由队友共享数学核派生的独立公式计算分支。两条路径使用相同的 RGB565 源帧、整次采样越界补黑规则、末邻点复制规则、源读缓存和人工访存后端；分别核对各自整数标准，再比较相对精确浮点映射的误差。队友原仓库保持不变。

## 实现与来源

原路径仍为 `src/remap_frame_writer.v`，串行或快速网格 mapper 可选。新增 `formula/brown_mapper_pipeline.sv` 在 FPGA 内直接计算 Brown 四参数多项式，`formula/brown_frame_writer.sv` 将其接入本项目的 RGB565 插值和逻辑像素读写接口。

数学流水线取自团队私有库 `wxyd-l/mes50hp-distortion-correction` 的本地提交 `faf35a4`，原文件为 `distortion_fpga/rtl/distortion_mapper.sv`，SHA256 为 `50f36d36201ce5884033f72bfb059e705445037ed872df208fae0648069f4eaf`。仅新增来源注释并重命名模块，保留原算术。该来源不代表允许公开发布或重新许可；交付包仍按团队内部协作使用。

本项目新增独立 Python 数值适配 `../algorithm/polynomial.py`、RGB565 帧写出包装、同源对照工具及测试。没有将队友的 RGB888 插值、direct-mapped cache 或 DDR 读桥直接拼入 RGB565 路径；其地址和存储布局必须另行适配。

## 支持范围

| 项目 | 原查表路径 | 新公式路径 |
|---|---|---|
| FPGA 坐标产生 | 插值预计算的网格节点 | 直接计算 k1 k2 p1 p2 |
| 当前模型能力 | 软件生成的有限映射，包括 Brown 五参数和已支持的三维旋转 | Brown 四参数，k3 必须为零；平面逆仿射 |
| 参数更新 | 完整加载另一库，在安全帧边界换表 | 接受 start 时锁存十四个参数 |
| 当前坐标格式 | 配置 Q8 或 Q16 | 固定 Q16.16 |
| 当前像素插值分数 | 使用坐标小数位 | 使用全部 16 位小数 |
| 像素与地址 | RGB565，行主序逻辑像素索引 | 相同 |
| 当前处理调度 | 每次处理一个像素 | 相同的单像素串行取样基线 |

公式导出拒绝非零 k3、三维 pitch/yaw、参数或运行阶段溢出，不会丢弃不支持的参数。硬件发生运行时溢出时仍输出对应黑像素，计入 `overflow_pixels`，该像素也计入 `invalid_pixels`，不发源读请求。真实 120° 镜头不能仅凭角度选择 Brown 或鱼眼；当前公式核不支持鱼眼。

公式核没有坐标 LUT，但有乘法器、寄存器等硬件成本。十四个参数仅占 56 字节，不能把它与查表总资源直接相减来估算节省。1080P 查表每库 17080 字节，双库四副本快速 mapper 的逻辑 LUT 存储为 136640 字节；实际 DSP、BRAM、Fmax 和功耗都须分别综合测量。

## 同一人工场景的数值结果

场景使用原人工 Brown 参数、30° 中心裁剪和 0.5 px 源坐标边距。1080P 内参仅按像素中心端点缩放示例，不是 OV5640 真实模式参数。源图为同一数值测试图案，高位截断为 RGB565。网格间距 32，网格插值权重精度 16 位。

| 分辨率 | 方案 | 对精确映射最大坐标误差 | 对精确浮点 RGB565 标准不同的像素数 |
|---|---|---:|---:|
| 1280×720 | 公式 Q16 | 0.003112 px | 6944 |
| 1280×720 | 查表 Q8 | 0.034202 px | 45077 |
| 1280×720 | 查表 Q16 | 0.032055 px | 44502 |
| 1920×1080 | 公式 Q16 | 0.006874 px | 31220 |
| 1920×1080 | 查表 Q8 | 0.024329 px | 69676 |
| 1920×1080 | 查表 Q16 | 0.021649 px | 67691 |

以上场景三方案均无无效坐标，与精确浮点掩码的有效性分歧均为零。公式版不同像素的各通道最大差为 RGB565 原生通道的 1 级，不是 RGB888 灰度的 1 级。高频人工图案会放大取样位置差异，像素计数不能用来评价真实镜头画质。

本例增加节点小数位不能消除网格空间近似误差；缩小网格间距是另一种需要权衡存储的选择。公式版在本例坐标误差较小，不表示它在所有标定或零畸变场景中都更精确，也不表示资源或速度更优。

## RTL验证

公式版的人工 720P 及 1080P 帧分别实际核对 921600 和 2073600 个坐标、像素及写入地址，均通过，无溢出。当前 1080P 公式版渲染 70066051 个周期；Q16 快速查表版同输入、同缓存和同人工后端为 57619135 个周期。两版的源地址轨迹略有不同，因此缓存未命中数量也不必完全相同。

这说明当前单像素串行包装下，公式版在该场景需要更多渲染周期；不能把比例换算为实板加速比或实际帧率。数学核 12 级连续流水与快速查表 5 级流水均不等于整个帧处理模块每拍一个像素。

同一人工 1080P 的 Q8 快速查表版也逐像素通过，渲染 57626494 周期、8178203 命中及 116197 未命中。三方案当前包与源码校验通过后已汇总在 `out/mapper_comparison/center30_1080/rtl_comparison.json`；三方案输出允许因数值近似不同而存在差异，不能拿公式输出直接作为查表版逐位标准。

十组 41×25 人工公式回归包括恒等、各畸变系数、负半像素边界、负 30°、中心裁剪 45°、90° 和故意溢出。每组分别检查连续流水与全局 CE 停顿，1025 个 token 的连续测试需 1036 个使能边沿；并检查帧中外部参数变化不污染当前帧、随机源读取/写入等待、持有写出时联合复位及恢复。溢出帧的 1025 像素全黑，源读次数为零。

软件当前共 143 项通过，算法 102 项、RTL 参考和交付工具 41 项。原四组精度/mapper 回归和两组独立缓存回归继续通过。完整源码校验和实际 marker 见 `out/formula-*/result.json`、对应日志及 `TEST_REPORT.md`。不把 Python 数值结果当作 RTL 仿真结果。

## 复现与更换输入

在项目根目录先生成同源标准包，再执行三方案 RTL 对照：

```powershell
.\rtl\run.ps1 tools/compare_mappers.py --synthetic-size 1920 1080 --angle 30 --out out/mapper_comparison/center30_1080
.\rtl\run.ps1 tools/run_mapper_comparison.py --directory out/mapper_comparison/center30_1080
```

`comparison.json` 是数值误差报告，`rtl_comparison.json` 是三方案各自通过记录汇总。实际报告路径随包内容校验码改变。若三个当前包已分别仿真过，可加 `--summarize` 只汇总已有结果；它会检查包和源码校验，缺失或过期时报错，不冒充重新仿真。

更换真实输入时取消 `--synthetic-size`，使用实际模式的相机配置和未缩放原始 PNG：

```powershell
.\rtl\run.ps1 tools/compare_mappers.py --camera C:/project/camera_real.json --input C:/project/raw_frame.png --angle 20 --border crop-center --out out/mapper_comparison/real_case
.\rtl\run.ps1 tools/run_mapper_comparison.py --directory out/mapper_comparison/real_case
```

上述 `C:/project/` 为用户需替换的示意路径，不是项目已有真实标定。输入尺寸必须与标定一致，不自动缩放；输出不可覆盖输入所在目录。真实输入数据不会被交付脚本自动打包。

`./rtl/run.ps1 test` 现在包含十组公式回归；仅生成小帧公式回归可用 `tools/formula_regression.py`。ModelSim、NumPy、Pillow 必须可用。

## 板级接口与接入条件

公式 wrapper 的 `parameters[447:0]` 以低位字段先排列：a00、a01、a02、a10、a11、a12、k1、k2、p1、p2、fx、fy、cx、cy，每项为 signed32。逆仿射用 Q4.28，中间量及畸变系数为 Q8.24，源相机内参和输出坐标为 Q16.16。系数量化 ties-to-even，乘积运行时算术右移截断，像素最后一次四舍五入并列时向正无穷舍入。

`start && start_ready` 才接受新帧并锁存参数；忙时 start 被拒绝并记录协议错误。`wr_valid && wr_ready` 表示接受一个目标帧像素，等待期间地址和数据保持。`done` 只表示最后一个逻辑写入被接受，不表示 DDR 已可见或显示已换帧。同步低有效复位会中止处理，源读后端和缓存必须共同复位或可靠清空旧事务。

wrapper 本身不包含缓存，测试平台外接与查表版相同的二路缓存。调用方在源帧内容或基址变化时必须先完成缓存无效化，处理期间源帧保持不可变；目标帧使用独立缓冲。缓存、帧所有权、物理地址、stride、CDC、显示换帧和写入完成屏障仍是板级职责。

后续以同一真实帧比较图像质量，再在同一器件、时钟约束和 DDR 条件下比较综合资源、吞吐和延迟。公式核的三维齐次变换、鱼眼模型、RGB565 的真实 Pango DDR 桥和多未完成请求流水仍需另行实现，当前对照版不能直接烧录。
