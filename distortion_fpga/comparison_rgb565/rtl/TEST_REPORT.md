## 实际 Verilog 仿真

两套权重精度 WEIGHT_FRAC=16 与 8 × 两种 engine 查表实现 USE_FAST_MAP=0 与 1，以下内容在四组组合中各执行一次：

- RGB565 插值 4,096 组：随机四颜色、同色、极端颜色、接近端点的权重。
- signed int32 插值 2,048 组：正负随机值、INT_MIN/MAX、0 与 1 的权重端点、负半值舍入。
- 随机 CE 与 valid 气泡：检查三个有效时钟沿的延迟、数据/标签对齐、停顿保持及复位不受 CE 阻止。
- Gamma：全部 65,536 个 RGB565 码分别检查启用与旁路，并同时检查空表的恒等实例；随机 CE/气泡和标签对齐。
- 坐标 mapper 与像素 engine：分别对恒等表、畸变加旋转表各检查 512 个坐标；另有切换前后和复位后的少量核对。
- 35×23，step=8，包含短末单元；最终边界、负/超界坐标和四邻居取样均覆盖。无效取样必须零次访存，有效取样必须四次访存。
- 两套表切换、非活动表装载时旧表继续使用、拒绝在 token 未完成时切换、拒绝不完整提交/乱序写、部分覆盖与事务未完成时复位、完整重装后恢复。
- 请求等待时地址稳定、输出等待时数据稳定、读响应的随机延迟、写入的随机反压。
- 每套精度输出四个 805 像素整帧，逐像素、逐地址检查，核对完成信号、无效计数和访存总数。

十六个小整帧全部通过。16 bit 权重的旋转表无效像素 87，8 bit 为 86；这是有意允许的精度差异，不使用同一标准文件强迫两者相等。两种查表实现的输出逐位相同。

并行查表额外核对五批各 512 个 token，含恒等/旋转表、连续输入、随机气泡/下游等待、排空后切表、输出等待时不切表以及流水线中途复位。每批无停顿的 512 个坐标在 517 个周期内消费完，验证五级流水后持续每拍一个坐标，而不是用软件运行速度推断。该单独测试在四组回归中均执行。

## 完整 1280×720 帧

输入为 `algorithm/out/complete_demo/input_synthetic.png`，表来自 `rotate_keep`，人工 Brown 四参数并合成 20 度旋转。标准由整数模型生成；实际 RTL 重新读节点和源像素后生成输出，不将标准输出喂给 DUT。

- 串行/并行查表分别比对 921,600 个输出 RGB565 像素及线性地址，均与同一标准相同。
- 无效像素 97,364，与硬件计数一致；这些像素补黑且不读源帧。
- 串行查表 44,514,534 个、并行查表 37,140,721 个渲染时钟周期，包含随机源读等待和目标写反压，周期数减少约 16.6%。不能把这项直接当作实板加速比。
- 源帧、输出帧各 1,843,200 字节，单坐标表 7,872 字节；串行双表 15,744 字节，并行四份双表 62,976 字节（逻辑表字节数，不是 BRAM 实测占用）。
- 硬件整数坐标 vs 同一浮点网格：最大欧氏误差约 0.002840 px，P99 约 0.002587 px，有效性分歧 3 像素。
- 同一表的浮点网格 vs 完整映射最大误差约 0.114522 px。这不是上一个误差指标；真实镜头和最终图像质量尚未验证。

周期数不是 FPGA 时序收敛结果，也不是实时帧率。整帧 writer 测试默认不接 Gamma；Gamma 通过的是独立模块测试。

## 新增缓存及联调工具验证

缓存独立测试两组，每组 5,138 个逻辑请求，返回数据与软件 LRU 计数一致，包含等待、无效化、部分补读/输出保持时复位、提前/缺失 last、无请求响应及错误恢复。复位期间所有握手关闭。

缓存 + 快速 mapper 的两组 720P 帧各 921,600 像素逐位通过：30° 中心裁剪 3,665,207 命中/21,193 未命中，24,095,481 渲染周期；20° keep 为 3,223,833/73,111，25,121,150 周期。软件模型及硬件补读 beat 数逐项吻合。后端是人工块模型，不能与原像素后端的周期直接推断实板加速比。

35×23 恒等源帧 805 像素，末块补 11 个安全 padding 像素；两套权重/两种 mapper 四组全帧通过，均 3,169 命中/51 未命中。详见 `CACHE_INTERFACE.md`。

导出帧比较的六组人工故障已生成；标准及明确解码的 BGR 大端 stride 文件一致，红蓝/字节/翻转提示可定位，单像素最低位错误准确报 1 个。均非真实板上导出，详见 `FRAME_COMPARE.md`。

## 1080P及宽视角人工整帧

新增 1920×1080 人工数值图案，30° 中心裁剪，源坐标安全边距 0.5 px，网格间距 32、坐标 Q8、插值权重小数位 16。使用快速 mapper 和 32 KiB 数据容量二路缓存（每块 16 RGB565 像素，512 组），逐个核对 2,073,600 个输出像素、地址与标签，全部通过，无效计数 0。

人工块后端包含等待，渲染 57,626,494 周期；8,178,203 次命中、116,197 次未命中、1,859,152 个补读 beat，均与软件标准一致。结果在 `out/package-8a5ce853bfe4-fast-cachel4s9/result.json`；测试包在 `out/demo1080p/`。双库四副本 LUT 的逻辑存储共 136,640 字节，不是 PDS 综合后的 BRAM 数量。

这次 1080P 测试不同于前述 Python 恒等坐标测试，实际执行了整帧 RTL，但只验证人工参数下的快速 mapper、缓存及权重 16 组合。原示例内参的端点缩放不等于真实 OV5640 模式转换，图案也不是摄像头拍摄；不据仿真周期声明实板帧率。宽视角测试定义见 `../algorithm/WIDE_ANGLE.md`。

宽视角人工 Brown 模型的正 60° 中心裁剪也完成同配置整帧 RTL 核对：1280×720 的 921,600 个像素、地址与标签全部通过，无效计数 0；24,176,748 周期，3,663,578 命中、22,822 未命中、365,152 补读 beat。报告在 `out/package-bb6bc2df27a1-fast-cachel4s9/result.json`，测试包在 `out/wide60/`。源数值刺激沿用原 720P 人工输入，并非此宽视角模型的真实拍摄或质量评测。
