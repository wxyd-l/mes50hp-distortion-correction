# 软件与RTL共同数值契约

坐标定义：u向右、v向下，像素中心为整数，输出网格到输入图像取样坐标。所有32位定点数均为二进制补码；本文Q总位数包含符号位。

|参数/变量|格式|说明|
|---|---|---|
|a00 a01 a02 a10 a11 a12|signed32 Q4.28|输出整数像素到理想归一化坐标的逆仿射；范围[-8,8)|
|x y、k1 k2 p1 p2及内部多项式|signed32 Q8.24|范围[-128,128)|
|fx fy cx cy、src_x src_y|signed32 Q16.16|源相机内参和映射像素坐标|
|u v|unsigned16|输出像素整数索引|
|wx wy|unsigned8|源坐标小数部分的高8位，即[15:8]|

采用算术右移向负无穷截断，不是四舍五入。乘积先保留64位。归一化的完整64位乘加为 `(a00*u + a01*v + a02) >>> 4`，y同理。不得先把倒焦距量化到Q16.16，1080p图像中会累积可见的坐标误差。

定义 `M(a,b) = (signed64(a)*signed64(b)) >>> 24`，然后检查是否可用signed32表达。

```text
x2 = M(x,x); y2 = M(y,y); xy = M(x,y)
r2 = x2 + y2
r4 = M(r2,r2)
s  = 1.0 + M(k1,r2) + M(k2,r4)
xd = M(x,s) + 2*M(p1,xy) + M(p2,r2+2*x2)
yd = M(y,s) + M(p1,r2+2*y2) + 2*M(p2,xy)
src_x = ((xd*fx) >>> 24) + cx
src_y = ((yd*fy) >>> 24) + cy
```

系数导出及运算每个阶段检查范围。RTL发生溢出仍产生对应输出token并置overflow；集成核输出黑色并记录本帧错误，不能丢像素或使用回绕坐标。

双线性每个RGB通道使用四邻点 `(x0,y0),(x0+1,y0),(x0,y0+1),(x0+1,y0+1)`，x0/y0为算术右移16位后的floor。各邻点越界独立补0。先算完整四项加权和，最后统一 `(sum+32768) >> 16`。这与OpenCV默认INTER_LINEAR的1/32权重表不逐位相同，因此坐标准确度与像素插值准确度分别报告。

数学核采用同一时钟、同步低有效复位和全局clock enable；ce=0时包括valid、像素编号和overflow在内的全部流水线状态保持。配置必须在流水线空闲时切换。帧集成核在接受start时锁存所有参数，支持处理中改变外部配置而不污染当前帧。

抽象像素内存使用32位字存储RGB888，低24位为0xRRGGBB；请求地址单位是**字节**，地址 `(y*WIDTH+x)*4`。请求/响应均为valid/ready，最多一个未完成请求。它不是厂商DDR端口；已由单独的pixel_read_cache和pango_read_bridge实现32B行缓存与端口转换，整合在remap_ddr_read_top。

`start`须在空闲时给一个时钟周期的脉冲；忙时的start被忽略，持续拉高则下一帧空闲时会再次启动。同步复位会丢弃当前帧；内存端也必须同时清除在途请求/旧响应，因为抽象接口没有事务ID，不能把旧帧回包用于新帧。

集成顶层在`start && start_ready`时锁存参数并使cache失效。源帧须提前写入DDR字节地址0，处理期间保持不变；本版本没有帧base寄存器或捕获写路径。cache将4字节像素请求合并至32字节行，读桥将行的字节地址右移2转换为Pango x32 word地址，ARLEN=0表示单个256位beat。读桥一次只允许一个在途请求；回包先完整存入寄存器，再由valid/ready送往cache。

`rsp_error[0]`为地址未对齐、`[1]`为超出1GiB、`[2]`为RID/RLAST错误。cache拒绝错误回包入库并向像素核返回0；集成顶层`memory_error`保持到共同复位。它与数学溢出的`frame_overflow`分开，防止将协议错误误当标定参数问题。物理DDR不返回时本桥会等待；任何看门狗恢复都必须同时处理旧事务，不能只重置桥。
