# 硬件到手后的逐步接入与验收

当前状态：只有离线算法/RTL与厂商材料；本清单各硬件项均未执行。每一步保存源码提交或文件SHA256、PDS/IP版本、运行参数、日志/波形和结果，失败停在本层定位，不能用后级图像掩盖前级错误。

## 必需物料

- 与资料匹配的MES50HP核心板/底板、厂商要求的配套电源、兼容的JTAG下载器与线。
- 一路视频源和实际镜头：若走厂商10例程，使用电气接口与引脚兼容的OV5640模块及相应转接线；若走HDMI输入，使用能输出目标格式的摄像头。两条路径择一即可。
- HDMI线及支持目标时序的显示器；开发电脑。电脑向板输入已知图像时需额外一条HDMI连接。
- 用于真实标定的平面棋盘格/圆点板和可靠的方格尺寸测量；标定板应平整、格点清晰。
- USB串口线用于状态/错误计数记录（若JTAG逻辑分析足够，串口并非首次点亮前提）。

不要求先买额外采集卡。若需要输出像素级外部核验，可先实现DDR帧回读/校验接口；若以后选择采集卡，应另验证其色彩范围/色度抽样，否则其图像不可直接当逐像素真值。

## 分层验收

| 步骤 | 做什么 | 必须观察/记录的信号或数据 | 成功条件 |
|---|---|---|---|
| 1. 实物与约束核对 | 记录PCB版号、FPGA封装、DDR丝印；将自用顶层每个端口逐项对照原理图与手册 | 全部PAD/电平、差分对、DDR专用约束、外设复位 | 无悬空必需引脚、无复用冲突、无未知bank电压；特别排除06例程P26旧约束 |
| 2. 原始DDR工程 | 用正确器件和实物DDR参数构建07例程；保存时序及资源报告 | `pll_lock`、`ddr_init_done`、读写计数、错误地址/期望值/实得值 | 校准每次上电成功，地址递增/walking bit/伪随机读回一致；覆盖跨行/跨bank/高地址边界 |
| 3. DDR持续负载 | 单写、单读、交替读写、不同burst长度 | 有效beat数、AR/AW等待周期、最大返回空隙、温度/运行时长 | 报告实测持续MB/s与最坏停顿；不以3.2GB/s理论峰值作通过线 |
| 4. 视频输出基线 | 生成已知彩条、坐标网格/灰阶，先720p30 | 像素时钟、HS/VS、DE每行有效数、每帧行数、MS7210初始化 | 显示稳定，1280×720活动区计数准确，RGB颜色顺序和范围正确 |
| 5. 视频捕获基线 | 接摄像头或HDMI已知图像，关闭畸变 | `vin_clk`、VS边沿、DE、每行/每帧像素计数、输入FIFO溢出 | 无丢行/错位，彩条/格点在回读帧符合预期；确认相机RGB565字节序或HDMI RGB888顺序 |
| 6. 整帧所有权 | 采集写DDR并按完整帧发布，显示读取另一已完成帧 | frame ID、FREE/WRITING/READY/READING状态、未完成读计数 | 输入/输出异步及丢帧情况下不读正在写的帧；无撕裂；只在帧边界交换 |
| 7. DDR适配器 | 先固定地址/长度花样测试，再cache miss/hit测试 | byte地址、IP word地址、AR/READY、RVALID/RLAST、FIFO水位、计分板 | 32B对齐映射正确，每请求返回指定邻域；发请求前已预留整个返回容量；随机停顿不溢出 |
| 8. 恒等重映射 | k1=k2=p1=p2=0、无仿射，运行真实内存路径 | 每像素坐标/邻点、输出CRC、overflow、帧像素数 | 输出与相同格式的软件定点模型逐像素相同；右/下边界及负坐标补0规则一致 |
| 9. 已知畸变与旋转 | 加入合成参数，测0/90°和正负切向项 | cache miss、读字节数、计算周期、输出FIFO最低水位、帧率 | 软件定点模型一致；不混用整型坐标与定点小数；90°不产生未计入的突发浪费 |
| 10. 真实标定 | 固定镜头焦距/对焦/分辨率，采集不同姿态和全视野标定板 | 原图、角点、训练/留出图分割、K、k1/k2/p1/p2、重投影/直线误差 | 留出图误差与校正后直线性确有改善；报告FOV裁剪与无效像素比例，不能只展示一张好看的图 |
| 11. 动态参数 | 连续视频中改变参数、旋转/仿射配置 | 接收参数版本、活动版本、SOF、帧ID、cache frame tag | 仅帧边界原子切换，整帧参数一致，无旧帧cache污染 |
| 11a. 三维姿态 | 使用`pose`生成yaw/pitch/roll配置，选`PROJECTIVE=1, POSITIVE_DEPTH=1` | 齐次分母、17词参数版本、overflow、有效视场 | 与定点参考逐像素匹配，俯仰透视与平面旋转可区分；负深度配置不读源像素 |
| 11b. Gamma预处理 | 在源帧写入前接入`gamma_stream`，依次固定／旁路／自适应 | 原始亮度sum/count、当前bank、SOF/EOF、增强源帧回读 | 每源像素统计一次，帧内bank不变；暗亮阶跃响应与软件一致；记录曝光设置与颜色对比 |
| 12. 分辨率与压力 | 720p通过后分别1080p30、1080p60，覆盖突发延迟 | PDS最坏时序、CDC、资源、丢帧/underflow/overflow、实际频率/时长 | 报告达到的持续帧率与错误计数；目标未达到时定位计算/DDR/显示瓶颈，不修改标签假称达标 |

## 必须先约定的协议细节

- 当前 `remap_frame_core` 是单未完成读的功能基线，`mem_req_addr`是byte地址，RGB888放在32位word低24位。`remap_ddr_read_top`已将它与32B direct-mapped cache和Pango单beat读桥连接并通过模拟DDR回包测试；尚无输出tile、多未完成读、真实厂商DDR IP或视频写入。上述步骤7的厂商模型/物理验证与实时吞吐优化仍待完成。
- `mem_rsp_valid`必须保持到`mem_rsp_ready`接受。即使内存允许零延迟，也不能在请求当拍发一个没有被ready接受的脉冲后丢弃。
- 同步低有效复位中断请求时，外部adapter必须一起flush或drain旧事务；接口无transaction ID，旧帧回包不能在复位后被新帧接受。
- `start`在空闲时按电平接受；单帧运行应发单周期脉冲。处理中`start`被忽略；一直保持为1会在帧完成后启动下一帧。
- 同时启动/切参前先确认流水线已空。输出`out_valid`遇反压时须保持RGB/坐标/last稳定；显示器端不能反压，应由输出FIFO/帧缓存承担停顿。
- 将负坐标用算术右移求floor，例如Q16.16的-0.25取x0=-1、小数0.75，四邻域逐点判界；不要转unsigned后再比较。
- 自适应Gamma的统计必须在原始源RGB流上完成，增强输出写入源帧，不能在随机四邻取样处重复统计。SFR测量按实际编码线性化，并记录矫正前后的图卡尺度与局部倍率，命令见`docs/quality_metrics.md`。

## 验收记录模板

每次记录：日期、板卡/镜头ID、工程版本、PDS/IP版本、bitstream SHA256、输入格式/参数、输出分辨率和帧率、总帧数、错误计数、DDR实测流量/最大停顿、FIFO最小余量、资源/时序报告路径、软件参考版本、逐像素/标定误差。将“仿真通过”“综合通过”“时序通过”“真实板卡通过”“真实镜头验证”分别标注，避免互相替代。
